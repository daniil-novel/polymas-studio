# 06. Визуальная спецификация PolyMAS Studio

Версия 0.1.0. Дизайн настольного редактора и рабочего пульта. Три PNG задают направление; интерактивный макет уточняет основные взаимодействия. Ни один из них не является исполняющей платформой.

## 1. Визуальная идея

Тёмная рабочая область знаний с большим графом в центре, устойчивой навигацией и компактным контекстным инспектором. Агент — отдельный узел. Свечение используется только для наблюдаемой активности. Большая часть интерфейса спокойная, без непрерывного движения.

Заимствована идея пространственной навигации по знаниям, знакомая по Obsidian. Логотип, компоновка деталей, состояния и визуальные элементы PolyMAS самостоятельные.

## 3. Сетка и области

Для 1600×1000:
- Header 54 px.
- Sidebar 220 px, диапазон 180–300; компактное состояние 56 px.
- Inspector 320 px, диапазон 280–480; при нехватке места drawer.
- Event panel 180 px, диапазон 120–400.
- Canvas получает оставшееся пространство.
- Отступы формы 24 px; расстояние между секциями 24 px, полями 16 px.
- Кнопки/поля минимум 36 px, primary actions 40 px; основная hit-area ≥ 32×32 px.
- Мастер MCP 460–560 px; модальная форма архитектуры до 880 px.

Широкая пустая полоса вокруг графа помогает читать связи. Чрезмерно плотное расположение всех подписей запрещено. Холст не заполняется декоративными виджетами.

При 1280×800 inspector по требованию, журнал collapsible. Системный scaling 200% не создаёт недоступных кнопок; допустима прокрутка формы.

## 4. Компоненты

| Компонент | Обязательные состояния |
|---|---|
| Button | default, hover, pressed, focus, disabled, pending |
| Toggle | off, on, disabled; health отдельно |
| Number stepper | целое, min/max, invalid, keyboard; не заменяется только slider |
| Provider select | available, unavailable, planned, auth_required |
| Status badge | иконка + текст, не только цвет |
| Agent node | idle, running, queued, waiting, failed, stale, selected |
| Edge | configured, delivered impulse, memory read/write, failed |
| Role editor | dirty, saved version, validation errors, diff |
| MCP row | unconfigured, tested, enabled, degraded, revoked |
| Artifact card | partial, ready, accepted, rejected, unavailable |
| Timeline row | selected, live, recorded, gap/stale |
| Drawer/modal | keyboard focus trap, escape, saved/unsaved state |

Число N имеет обычное поле и presets; slider логарифмический 1–5000. Положение slider не является источником точности. C имеет отдельное поле и пояснение «Остальные в очереди».

## 5. Анимация и связь с событиями

- Running node: мягкая пульсация внешнего контура с периодом 1.8 s, не более 15% изменения opacity.
- delivered_to_context: точка вдоль ребра 600–1200 ms, направление from → to.
- tool call memory read: фиолетовый импульс к источнику; успешный ответ — обратный импульс.
- queued message: маленький значок ожидания у ребра/получателя, без эффекта уже доставленного сообщения.
- failed delivery: красный короткий штрих с ошибкой в журнале, без зацикленного мигания.
- selected node: постоянный контур, не собственная «работа».
- hover/панель: transitions 120–180 ms.
- reduced motion: никакой пульсации/движущихся частиц; статичные значки и число событий.

Проекция сохраняет состояние по event ID. Частицы могут агрегироваться, но число событий и журнал остаются точными. При stale heartbeat UI выключает активный эффект, пока связь не подтверждена.

## 6. Референс 01: граф

[Открыть PNG](references/01-agent-graph.png)

Левая навигация + дерево холонов, граф в центре, инспектор справа, временная шкала снизу. Мята для работы, фиолетовый для памяти. Один выбранный агент имеет задачу, роль, инструменты и диалог.

Уточнения для реализации:
- Рисунок содержит условные точки/счётчики. Реальный UI вычисляет N из registry.
- Не все узлы должны светиться. Только state running имеет свечение; idle серый.
- Строки журнала должны сортироваться по выбранному времени/sequence; порядок условных строк PNG не является контрактом.
- «Общая память» — типизированный источник, отдельно от N.
- Верхний demo banner применяется только к макету/демопроекту, не к обычному live run.

## 9. Интерактивный макет

[Открыть prototype.html](prototype.html)

Локальный макет позволяет:
- переключать Граф, Агенты, MCP, Задачи, Знания и Запуски;
- выбирать графовые узлы и читать инспектор;
- открывать архитектуру, менять 1/10/24/1000/5000 экземпляров и C;
- включать память и координатора независимо;
- создавать демонстрационные экземпляры;
- запускать/приостанавливать демонстрационные события;
- просматривать демонстрационный мастер MCP.

Макет не читает файлы пользователя, не запрашивает API, не запускает Codex и не сохраняет секреты. Он предназначен для ревью структуры, плотности и логики основных контролов. Демо-счётчики и события явно обозначены; перезагрузка возвращает исходный сценарий.

Не все production-состояния интерактивно реализованы в макете. Полный контракт экранов находится в UX-spec; replay, RBAC, настоящий OAuth, виртуализация больших таблиц и восстановление — требования к будущему приложению.

## 10. Передача в реализацию

Сначала UI shell и дизайн-токены, затем доступный список/инспектор, затем граф с теми же read models. Нельзя реализовать вторую независимую модель данных внутри canvas.

Выбор/поиск, фильтры и команды отправляются общему UI store; изменения конфигурации проходят через backend validation. UI не считает успешным запуск/подключение по клику кнопки — только по подтверждённому событию.

Для каждого компонента сохранить примеры default/empty/error/stale и клавиатурного использования. Дизайн принимается по читаемости, точным состояниям и выполнению сценариев, а не только по совпадению PNG.
