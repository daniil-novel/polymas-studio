## [Unreleased]

### Changed

- Параллелизм frontend-проверок ограничен двумя процессами для больших JSDOM-сценариев; таймауты и утверждения тестов сохранены.

- Сохранённый результат старой задачи доступен независимо от рабочего набора планировщика; карточка больше не зависит от наличия задачи в оперативной памяти.

- Кнопка общей остановки доступна для задач в очереди и ожидании, включая приостановленную систему; запускать очередь для отмены больше не требуется.

- Состояние агентов теперь вычисляется независимо от окна последних задач: длинная история не скрывает продолжающуюся работу и не отключает остановку.

- Выбранный холон автоматически кадрируется по видимым узлам; скрытые агенты больше не заставляют группу сжиматься. Кнопка «Вписать граф» использует текущий фильтр.

- Зафиксирована предварительная квалификация Codex app-server 0.144.1: отдельный профиль пока не допущен, граница изоляции и реальное write-подтверждение требуют проверки.

- Подсветка нового события графа больше не ждёт следующего тика часов; счётчик и инспектор учитывают устаревший heartbeat, сохраняя возможность остановки задачи.

- На узком экране список подтверждений располагается над карточкой; параметры и сведения операции больше не сжимаются в узкую колонку. Размеры проверяются браузерной регрессией в CI.

- Фоновое обновление подтверждений сохраняет раскрытые сведения и положение карточки; ошибка обновления отключает решения до получения актуальных данных.

- Неиспользованное разрешение автоматически закрывается, когда его попытка больше не может выполниться; история больше не показывает завершённые попытки как доступные для записи.

- Диагностическое представление approval исключает содержание операции и её аргументы; точная карточка владельца сохраняется.

- Подтверждён реальный Codex MCP цикл поиска общей памяти и чтения provenance с приёмкой через UI; неуспешная приёмка при конфликте ролевого/задачного формата сохранена в evidence.

- README описывает существующие приложение/службу, установку из исходников, первые сценарии, расположение данных, проверки и оставшиеся production gates вместо прежнего статуса «только спецификация».

### Added

- Owner API дублирования сохранённой версии в отдельную роль v1. Повтор с тем же ключом возвращает исходную копию после перезапуска; запись роли, квитанции и истории атомарна. Экземпляры и MCP-привязки не копируются.

- Настройка дополнительных колонок каталога с сохранением отдельно для каждой рабочей области и возвратом стандартного вида. Скрытие полей сохраняет выбор и положение списка; ошибки локального хранилища и копирования ID показаны в интерфейсе.

- Восстановление выбранной старой роли из экрана сравнения: свежий предпросмотр изменений и всех полей, новая версия без переназначения агентов, сохранение черновика и проверка результата перед повтором после ошибки.

- Серверная команда восстановления старой роли новой версией с указанием источника в журнале. Старые версии, назначения и задачи сохраняются; устаревший повтор и переполнение номера отклоняются без записи.

- Сравнение любых двух сохранённых версий роли по всем полям, с фильтром изменений и чтением длинного текста по частям. Просмотр сохраняет черновик; новые данные не подменяют открытый снимок.

- Назначение сохранённой версии роли выбранным экземплярам с просмотром инструкции и MCP-привязок; поиск среди тысяч версий, проверка всего набора и защита от повторной записи после неясного ответа. Уже созданные задачи сохраняют исходные инструкции.

- Подготовка, просмотр по частям и скачивание конфигурации из настроек. Сохраняется показанная ревизия; отменённый/ошибочный ответ не создаёт файл. Интерфейс проверяет полный контракт без динамического исполнения кода.

- Переносимый JSON-экспорт архитектуры через owner API: все версии ролей и определения экземпляров, холоны, связи, ограничения и placeholders подключений. Сессии, локальные настройки MCP и приватная история исключены; схема и ограничение размера проверяются регрессионно.

- Массовый выбор экземпляров с сохранением при фильтрации и предпросмотром архивирования: точные ID, поиск/страницы выбранных, последствия для связей/MCP/координаторов, проверка занятости и запрет слепого повтора после ошибки.

- Атомарное архивирование до 5000 выбранных экземпляров через API; незавершённая или неизвестная попытка одного из них блокирует весь набор, файлы и история сохраняются.

- Переименование экземпляра из каталога с чтением свежих данных, сохранением черновика при конфликте и проверкой исхода после потерянного ответа; ID и история агента сохраняются.

- Поиск, фильтр состояния и сортировка в каталоге экземпляров; таблица тысяч агентов отрисовывает только видимые строки, показывает текущую задачу/холон/исполнителя и поддерживает переходы с клавиатуры.

- Проверка и переносимая нормализация отчётов CycloneDX: локальные пути заменяются вместе со связями зависимостей, повреждённые документы отклоняются, отсутствующие сведения о лицензии отмечаются в сводке.

- Экран истории запусков использует всю сохранённую историю с поиском, фильтрами и отдельными страницами задач; выбранный результат и черновик сохраняются при обновлении и поиске.

- API истории читает все сохранённые запуски и задачи страницами, с поиском и фильтрами; большие результаты и конфигурации не попадают в списки.

- Навигация по дереву холонов показывает всех участников и вложенные группы в графе/списке; из выбранного холона можно открыть задачу с уже заданным получателем.

- Перетаскивание узлов с сохранением положения, снятие закрепления и отмена жеста клавишей Escape. Ошибка сохранения требует обновления данных; исторический граф остаётся доступным только для просмотра.

- Сохранение и сброс позиции одного узла графа отдельной командой с защитой от устаревшей ревизии; права, роли и связи при перемещении сохраняются.

- Просмотр сохранённого ответа инструмента в карточке операции и скачивание JSON после проверки контрольной суммы. Загрузку можно отменить; смена операции отменяет прежний запрос файла.

- Owner API результатов и агентский инструмент чтения страниц; большие MCP-ответы больше не переполняют execute/status. Отзыв области прекращает агентское чтение, повтор не отправляет внешний вызов.

- Ограниченные страницы сохранённого результата операции с контрольной суммой; большие ответы не предназначены для повторной передачи целиком в MCP-сообщении. Подключение к экрану результатов следует отдельно.

- Исполнение одобренной MCP-операции в точном продолжении агента; ответ сохраняется вместе с исходом, повтор читает receipt. Обрыв, отмена, отзыв доступа и возможная частичная запись требуют сверки владельца.

- Агентские MCP-инструменты запроса точной операции и чтения решения; запрос и ожидание сообщения взаимно исключаются, а повтор сохраняет исходный ID и срок.

- Форма сверки неизвестного исхода: владелец записывает проверенный результат и заметку, повтор сохранения не дублирует запись и не вызывает инструмент; черновик сохраняется при обновлении карточки.

- Восстановление неизвестного исхода внешней операции после сбоя; повтор задачи и приёмка блокируются до записанной сверки владельца. Сама сверка не повторяет внешний вызов.

- Экран «Подтверждения» с исходным ресурсом, точными параметрами, фильтрами и решениями; состояние ожидания владельца видно в задаче, графе и записи запуска. После потери ответа требуется свежая карточка.

- Защищённый API подтверждений: список без содержимого операции, точная карточка с исходным адресом ресурса, причины недоступности и решение по показанной ревизии.

- Исполнитель сохраняет промежуточный артефакт перед ожиданием владельца и продолжает ту же сессию после решения, передавая идентификатор разрешённой операции.

- Продолжение после решения владельца с проверкой ревизии и срока разрешения; одобренная операция потребляется один раз, изменение доступа перед исполнением блокирует запись.

- Атомарное создание запроса разрешения вместе с продолжением агента: ошибка сохранения не оставляет зависшего резерва; целевой ресурс и права проверяет служба.

- Разрешение связывается одновременно с исходной попыткой запроса и конкретной будущей попыткой исполнения; прежние записи без такой связи не разрешают внешний эффект.

- Планировщик резервирует конкретный следующий turn для подтверждаемой операции, сохраняя очередь экземпляра без удержания вычислительного слота; отменённый номер попытки не переиспользуется.

- Состояние ожидания владельца в планировщике: отдельный process slot освобождается, причина ожидания сохраняется, подходящее продолжение получает новую fenced попытку; отмена и ранняя приёмка закрывают ожидание.

- Идемпотентный запрос разрешения на попытку: потерянный ответ не создаёт вторую операцию и не продлевает срок, решение сохраняется после перезапуска.

- Просмотр записанного запуска с исходной архитектурой, паузой/перемоткой/скоростью, переходом к сообщениям/чтениям/ошибкам и карточкой события; исторический граф использует собственное время и не отправляет управляющие команды.

- API записи запуска: исходная конфигурация, неизменяемые описания задач и страницы событий с фиксированной верхней границей; поздние события/текущие результаты не подменяют прошлое.

- Фиолетовые импульсы на графе от выбранной общей памяти к агенту после успешного MCP/knowledge read; ошибки, другие подключения, потеря связи и устаревшие события не подсвечиваются.

- MCP-инструменты поиска и чтения общей памяти: проверяют live/pinned memory source, разрешения роли/экземпляра и namespace; не выдают частные/истёкшие записи и журналируют чтение без текста утверждений.

- Чтение реестра знаний в пределах конкретного подключения: фильтр источника применяется до пагинации, а связи выдаются только при доступности обеих сторон.

- Экран «Знания»: регистрация источника, утверждения с версией/автором, фильтры и страницы, проверка человеком и направленные связи. Формы сохраняют ключ повторной команды при сетевой ошибке; поздний ответ другой карточки не подменяет происхождение.

- Защищённый API редактора знаний: источники/утверждения/связи, фильтры и provenance, идемпотентное сохранение и конфликт ревизии; автор пользовательских команд задаётся службой.

- Транзакционные команды знаний с durable idempotency и проверкой ревизии решения; постраничный поиск источников/утверждений/связей с Unicode-регистром, namespace/status/retention и ограничением объёма ответа.

- Execution pipeline проверяет постоянного владельца перед resume и при получении сессии; сохраняет session ID уже при начале диалога, включая неудачные turn. Ошибка события отменяет исполнителя и ожидает reap до освобождения экземпляра.

- Постоянный реестр владельцев Codex-сессий с восстановлением связей из runtime/task history и событий; конфликт старой истории откатывает миграцию, UUID нормализуется перед сравнением.

- Настольная оболочка Tauri для Windows: встроенный React, ограниченные IPC/capabilities/CSP, отдельная служба и OS vault profile, single-instance, tray и применение сохранённой политики закрытия. Добавлены воспроизводимые команды сборки и staging sidecar для CI.

- Диалог закрытия desktop: явный выбор фон/остановка, запоминание, отмена и сохранение окна при ошибке остановки; экран сбоя запуска предлагает reconnect без ручного control token.

- Сохраняемая настройка закрытия: фон, остановка либо повторный вопрос; первоначально выбор отсутствует, неизвестные действия отклоняются.

- Durable desktop-профиль: атомарное сохранение endpoint и ссылки vault перед adopt, защита параллельного старта, повторное подключение к прежнему PID и отложенная очистка старых credentials.

- Startup adoption для нативного запуска: задачи не исполняются до сохранения подключения, забытая служба закрывается по сроку без отмены очереди, позднее подтверждение отклоняется атомарно.

- Повторное нативное подключение к той же службе по записи port/workspaceId и ссылке OS vault; credential не сериализуется, несоответствующая рабочая область отклоняется.

- Нативный launcher отдельной службы: случайный credential, динамический loopback порт, ограниченное ожидание готовности, очистка неудачного запуска и явный drain при остановке.

- Нативный клиент службы: управляющий credential остаётся в Rust, разрешён только loopback API, ограничены размеры/время ответа, запрещены redirects и сохранены структурированные ошибки конфликтов.

- Ожидание в интерфейсе: спокойный узел графа, условие и срок, промежуточная сводка, отмена и автоматическое обновление после пробуждения.

- Полный цикл wait/resume в исполнителе: промежуточный артефакт, освобождение слота после успешного reap, автоматическое пробуждение и продолжение сессии именно этой задачи.

- MCP-запрос ожидания сообщения: сохраняет неизменяемое условие и deadline на попытку, проверяет отправителя и бюджет следующего turn, не освобождает ещё работающий процесс.

- Durable пробуждение ожидающих задач: только сообщение нужного запуска/адресата/correlation и разрешённого отправителя либо истечение срока; причина продолжения сохраняется вместе с событием.

- Состояние ожидания в планировщике: освобождение process slot, ограниченный срок, новая fenced попытка при пробуждении и запрет возобновления отменённой задачи.

- Межагентные инструменты gateway: разрешённые адресаты, идемпотентная отправка, доставленный inbox и подтверждение обработки с проверкой текущего запуска и обеих версий архитектуры.

- Постраничный inbox доставленных сообщений с проверкой получателя и запуска; очереди других запусков больше не вытесняют сообщения текущей задачи из входного batch.

- Исполнитель Codex подключает отдельный MCP bridge каждой попытке; credential живёт ровно до завершения execution pipeline и не содержит административных прав.

- Доверенный STDIO MCP bridge в отдельном процессе: только loopback, без proxy/redirect, ограниченный ответ и передача attempt credential через окружение.

- Поиск доступных MCP-инструментов и чтение через scoped gateway: пагинация схем, проверка live/pinned bindings, namespace, ограничение параллельных вызовов и реальные события вызова без содержимого источника в журнале.

- Отдельный credential агентской попытки: закрытый gateway не принимает токен редактора, не доступен браузерному Origin и отзывает доступ по завершении lease.

- Каталог и мастер MCP по референсу: Files/Neo4j/custom, STDIO/HTTPS, пошаговая инструкция, защищённые поля, обнаруженные инструменты, role/agent/holon bindings и явный toggle после проверки.

- Управление MCP через локальную службу: сохранение/проверка/выбор инструментов/включение с ревизиями, загрузка credentials из OS vault и очистка точных значений секретов в диагностике.

- Просмотр запусков и результатов: критерии, PID/попытка, артефакты, события, ручная приёмка/отклонение, отмена, сверка перед повтором, продолжение диалога и экспорт Markdown.

- Постановка задач агенту, холону и системе через UI: критерии, приоритет, зависимости, quorum/manual/first-accepted, новая сессия; отдельные черновики адресатов и идемпотентный повтор отправки.

- Редактор архитектуры: пресеты, независимые переключатели координатора/памяти, вложенные холоны с участниками и контрактами, направленные связи, C и бюджеты сообщений; защита устаревшего черновика.

- WebGL-представление реальных агентов: группы, направленные связи, подсветка выбора/работы, импульсы доставки, миникарта и масштаб; поиск, фильтры и виртуальный список используют одну проекцию.

- Общая проекция графа/списка: только наблюдаемая активность, истечение heartbeat и импульсов, явные разрешённые связи и отдельный узел памяти; детерминированная раскладка 5000 определений в worker.

- Полная исходная спецификация PolyMAS Studio, контракты, критерии приёмки и три дизайн-референса.
- План реализации небольшими проверяемыми срезами с историей Git и регрессионными тестами.
- Rust/React/TypeScript workspace, фиксированные зависимости, lint/type/build проверки и CI на Windows/Linux.
- Неизменяемые версии ролей и атомарное создание до 5000 независимых экземпляров с защитой от повторной команды.
- SQLite WAL: совместная транзакция данных и событий, optimistic revisions, cursor replay и согласованный backup.
- Топологии, вложенные холоны и явная адресация задач; независимые настройки координатора и памяти.
- Планировщик с ограничениями N/C, режимом start-all, отдельной приёмкой, приоритетами, зависимостями и fencing token.
- Контракт Codex 0.144.1: resolver бинарника, безопасная передача аргументов, точный resume и ограниченный JSONL-декодер.
- Надзор реальных процессов, Windows Job Objects, отмена, таймауты, backpressure и очистка чувствительных диагностических строк.
- Рабочий Codex exec/resume адаптер с проверкой сессии и результата; отдельная opt-in проверка реального провайдера.
- Надёжные межагентные сообщения: idempotency, inbox, доставка в контекст, подтверждение, TTL и ограничения циклов.
- Настройки MCP с отдельными состояниями включения и здоровья; файловый источник с доступом только внутри выбранных папок.
- Реальный MCP-клиент STDIO и Streamable HTTP на официальном Rust SDK, с таймаутами, списками инструментов и запретом перенаправления credentials.
- Секреты подключений хранятся в системном credential store; конфигурация использует непрозрачные ссылки, значения очищаются из памяти при освобождении.
- Одноразовые разрешения на точные операции: durable ledger, проверка аргументов, версии подключения, lease и срока действия до внешнего вызова.
- Доступ к MCP ограничен пересечением сохранённого снимка и текущих bindings: отзыв действует немедленно, новые grants требуют нового запуска.
- Граф знаний хранит версии источников, авторство, retention, отдельную проверку утверждений и связи supports/contradicts/derived_from.
- Неизменяемые артефакты с SHA-256, принадлежностью к агенту/attempt и проверкой содержимого; импорт ограничен workspace агента.
- Согласованные backup и восстановление в новую папку: SQLite snapshot, только связанные blobs, manifest, проверка hash/целостности до публикации результата.
- Workspace service: команды редактирования, атомарная история ревизий, блокировка от второго процесса и сброс неподтверждённого состояния MCP при изменении настроек.
- Очередь связана с durable engine: задачи хранятся отдельными записями, bindings и роли фиксируются на запуск, restart переводит незавершённые attempts в unknown без автоматического повтора.
- Локальный HTTP control plane требует отдельный токен и допустимый Origin; доступны сохранённое состояние, редактирование, история и cursor replay событий.
- Исполнительный pipeline связывает lease, отдельный процесс, bounded inbox, подтверждение stdin, PID/сессию и финальный артефакт с durable задачей.
- Запускаемая служба Codex с HTTP-командами задач, pause/cancel/accept/recovery, диагностикой версии/входа и корректным завершением процессов при остановке.
- React-оболочка редактора по дизайн-токенам: навигация, состояние workspace, счётчики registry, инспектор, журнал и явное состояние потери подключения.
- Форма ролей и экземпляров: версионирование, инструкция, критерии, sandbox, модель, массовое создание 1–5000, точный preview имён и защита открытого черновика от внешнего изменения роли.

### Fixed

- Массовое назначение роли отклоняет пустой набор, дубли и архивные экземпляры целиком; поиск выбранных агентов не становится квадратичным при 5000 определений. Уже созданные задачи сохраняют свои версии инструкций.

- Разрешение MCP привязано к запуску, namespace и hash области ресурса; подмена любого из них запрещает исполнение, прежние записи без области не могут быть одобрены для новых вызовов.

- Пересекающиеся подписи узлов скрываются по измеренным границам текста; длинное имя сокращается без разрыва Unicode-символа, полное имя экземпляра сохраняется.

- Автоматические группы графа больше не накладываются после добавления роли или памяти: учитывается радиус каждой группы, поля контуров масштабируются вместе с графом, ручные позиции сохраняются.

- Debug-формат запроса Codex и MCP launch больше не выводит prompt, аргументы запуска и значения environment; сохраняет только ограниченную техническую сводку.

- Нативная остановка ждёт освобождения workspace lock после shutdown; принятие HTTP-команды больше не считается завершением службы, восстановленный PID не используется для kill.

- Нативный IPC сохраняет тип и статус ошибки для форм, не отправляет уже отменённую команду и не импортирует browser credential в desktop sessionStorage.

- Контекст Codex явно задаёт идентичность agent/task/run и правило вызова полного имени из каталога MCP; короткий alias больше не предлагается как готовое имя функции.

- Передача входящих сообщений повторно проверяет текущие и сохранённые связи до чтения содержимого и ограничения страницы; отозванные отправители не вытесняют разрешённые сообщения.

- Входной batch учитывает JSON escaping: допустимое сообщение размером 64 КиБ больше не блокирует очередь, порядок доставки сохраняется в пределах 512 КиБ.

- Подпись выбранного узла графа использует контрастную тёмную карточку вместо стандартного белого фона Sigma; длинные имена ограничены по ширине.

- События MCP из Codex содержат только метаданные наблюдаемого действия; аргументы и полный ответ источника больше не дублируются в общей ленте.

- Выделен polymas_read_source с корректной read-only семантикой; даже разрешённый binding записи не позволяет вызвать write tool через этот интерфейс.

- Настроенные credentials очищаются и из успешных структурированных ответов MCP, если внешний сервер вернул их в содержимом или ключах объекта.

- Приёмка результата атомарно обновляет задачу и связанные артефакты; повреждённая ссылка откатывает всю операцию, включая события.

- Перенос между холонами пересчитывает автоматические координаты перемещённых узлов; закреплённые пользователем позиции сохраняются.

- Граф разрешений соответствует runtime: независимые экземпляры не получают отображаемых каналов, выбранный координатор связан с участниками при сетевом пресете.

- Компоновка формы ролей: убраны дублирующий заголовок и журнал, дополнительные параметры свёрнуты, предпросмотр и схема экземпляров расположены рядом.

- Проверка ссылок ограничена документацией проекта; сторонние зависимости больше не дают ложные ошибки.
- Junction/symlink не может перенаправлять папку агента или общую папку agents на чужое расположение перед запуском.
- Supervisor подтверждает полную передачу stdin отдельным событием; ошибка входного pipe больше не может скрываться за успешным выходом процесса.
- На Windows перед подтверждением stdin выполняется flush: shutdown буферизованного Tokio pipe сам по себе не ожидал завершения записи.
- Шаблон имени экземпляра поддерживает нумерацию {n:02}; неизвестный синтаксис отклоняется до создания агента.
