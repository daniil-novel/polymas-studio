# 04. Codex и MCP: настройка, диагностика, рецепты

Этот документ описывает будущие мастера приложения. Приведённые команды — инструкции для реализации и самостоятельной настройки, они не выполнялись в рамках подготовки спецификации.

## 1. Подключение Codex CLI

### Что видит пользователь

«Настройки → Исполнители → Добавить → Codex CLI».

1. Приложение находит установленный Codex, показывает путь и версию.
2. Если его нет, кнопка открывает [официальное руководство CLI](https://developers.openai.com/codex/cli). Встроенная установка скачивает только зафиксированную поддерживаемую поставку после выбора пользователя; не меняет глобальную установку автоматически.
3. Выбирается рабочая папка и профиль изоляции.
4. Выбирается способ входа.
5. Проверяются доступность CLI, авторизация и отдельно реальный запрос.

### Вход через ChatGPT

Пользователь нажимает «Войти через ChatGPT». Приложение запускает штатный codex login в собственном auth profile, открывает полученный официальный URL и ожидает завершение. Пароль ChatGPT вводится только на странице входа. Headless/device flow предлагается только при поддержке выбранной версии и окружения.

После входа UI показывает метод и состояние из доступной диагностики Codex. Сам факт наличия файла credentials не считается успешной авторизацией.

### Вход через API-ключ

1. Открыть [страницу API keys](https://platform.openai.com/api-keys) в своём OpenAI Platform аккаунте.
2. Создать ключ в нужном проекте с минимальными правами.
3. Вставить в защищённое поле PolyMAS; сохранить в OS credential store.
4. Выполнить проверку. Передача ключа Codex — штатным механизмом, например stdin для login --with-api-key, без помещения значения в argv или лог.

ChatGPT-вход и API-вход поддерживаются Codex для локальной работы; использование API тарифицируется отдельно от включённого доступа ChatGPT. Приложение не обещает наличие конкретной модели или объёма квоты до проверки аккаунта. [Codex authentication](https://developers.openai.com/codex/auth)

### Диагностика и ограничения

Состояния: not_installed, incompatible_version, not_authenticated, auth_detected, verified_request, quota_blocked, network_error, managed_policy_denied.

В продукте хранится собственная матрица adapter × CLI version × OS × auth method. Непроверенная версия получает статус «Совместимость не проверена» и не подменяется известной. Автоматическое обновление CLI во время run запрещено.

История и runtime-state привязаны к explicit session ID. Отдельные экземпляры не получают случайную последнюю сессию.

## 2. Общая модель MCP-подключения

MCP-сервер предоставляет инструменты/ресурсы; база, файловое хранилище или внешний сервис находятся за ним. «MCP Neo4j» и «Neo4j database» — два компонента, у которых могут быть разные адреса и ошибки.

Поддерживаемые базовые transports Codex: локальный STDIO и Streamable HTTP; для HTTP возможны bearer token/OAuth. Конфигурация сервера и его enabled/required/tool allowlist должны соответствовать конкретной поддерживаемой версии. [Codex MCP](https://developers.openai.com/codex/mcp)

Внутренняя модель:

| Поле | Назначение |
|---|---|
| id, recipeId, recipeVersion | Стабильная идентичность и закреплённый рецепт |
| publisher, sourceUrl, verifiedAt | Происхождение и дата проверки инструкции |
| transport | stdio или streamable_http |
| command/args/cwd | Только для локального процесса; без shell parsing |
| url/authMethod | Для HTTP; HTTPS для удалённого адреса |
| secretRefs | Ссылки на защищённые значения, не сами значения |
| enabledDesired, health | Желание пользователя и наблюдаемое здоровье |
| tools/capabilities | Выявленные возможности и версия protocol |
| bindings | Субъекты, namespaces, allowlist, read/write, required |
| timeouts, poolLimits | Ограничения ресурсов |
| setupGuide | Шаги, ссылки, источники каждого поля и тесты |

Сервер с динамическим набором инструментов перепроверяется. Добавление нового tool не расширяет allowlist ранее сохранённого binding.

## 3. Поведение переключателя

1. OFF → пользователь нажимает ON.
2. Если нет обязательных полей/credentials, открывается мастер; включение ещё не сохранено.
3. Приложение показывает, что будет запущено/какие адреса использованы.
4. Проверяет configuration syntax → transport → MCP initialize → auth → capabilities → разрешённую контрольную операцию.
5. Пользователь выбирает роли/агентов/холоны и права.
6. Транзакционно сохраняются enabledDesired и bindings. Только теперь появляется «Подключено».

Сохранённое включение с потерянной связью: ON + «Недоступно». Отключённое: OFF + «Отключено». Отозванные credentials: ON + «Нужен вход»; вызовы blocked.

OFF во время работы: немедленно запрет новых вызовов; отмена поддерживаемых in-flight; список зависимых задач. Для required подключения задачи переходят blocked. Старая история не удаляется.

В UI не смешивать «сервер настроен», «проверка успешна», «сервер включён» и «доступ выдан этому агенту».

## 4. Рецепт A: файловое хранилище

**Цель:** агенты читают знания из выбранной пользователем папки.

### Пошаговая инструкция в продукте

1. Открыть «MCP → Файлы → Настроить».
2. Нажать «Выбрать папку» и указать каталог знаний. Рекомендуется отдельная папка проекта. API-ключ для локальной папки не нужен.
3. Выбрать «Только чтение» и допустимые форматы. Системные каталоги и секреты не выбираются по умолчанию.
4. Подтвердить источник/версию устанавливаемого файлового MCP или выбрать существующий сервер.
5. Нажать «Проверить»: список разрешённых корней и чтение одного выбранного файла.
6. Выдать доступ конкретным ролям/холону. Нажать «Подключить».
7. При необходимости открыть «Знания → Индексация». Доступ к файлам уже возможен, индекс создаётся отдельно.

Референсный MCP — @modelcontextprotocol/server-filesystem. Он умеет и чтение, и запись; передача allowed directory сама по себе не делает сервер read-only. Ограничение roots обязательно: сервер требует хотя бы один разрешённый каталог. Если поддерживается Roots, клиент управляет ими; этот набор должен формироваться gateway из политики, а не из ответа модели. [Filesystem server](https://github.com/modelcontextprotocol/servers/blob/main/src/filesystem/README.md)

Read-only binding разрешает только обнаруженные инструменты чтения/списков/метаданных. Сервер запускается с файловыми правами чтения, если требуется строгая граница. Write tools отсутствуют в каталоге агента.

Проверки пути: canonical path, junction/symlink, UNC/съёмный диск, смена корня между проверкой и чтением. Для portable export путь заменяется alias knowledge_root.

Ошибки: папка отсутствует; нет OS-доступа; файл слишком большой; формат не поддержан; каталог вышел за разрешённый root; MCP binary отсутствует. У каждой ошибки своя кнопка исправления.

## 5. Рецепт B: Neo4j как графовая память

### Вариант B1: существующая БД и локальный MCP

Пользователь выбирает «Neo4j → Локальный MCP». Мастер объясняет: «Сервер MCP будет работать на этой машине и подключаться к указанной базе».

1. Открыть консоль/панель своей базы Neo4j. Если базы ещё нет, перейти по ссылке «Создать/установить Neo4j»; это отдельный сервис, возможные расходы не скрываются.
2. Взять адрес подключения, имя базы и credentials пользователя этой базы. При отсутствии прав создания ограниченной учётной записи обратиться к администратору базы.
3. В PolyMAS заполнить «Адрес БД», «База», «Пользователь», «Пароль». Пароль сохраняется в credential store. Для графа по умолчанию включено «Только чтение».
4. Выбрать установленный Python environment/MCP runtime либо установить закреплённый рецепт в изолированную среду PolyMAS.
5. Проверить запуск MCP и доступность БД по отдельности.
6. Выбрать namespace/схему знаний, разрешённые tools и участников. Для общей памяти нажать «Использовать как общую память» — это отдельная привязка.

Официальный self-hosted quickstart использует пакет neo4j-mcp-server и запуск python -m neo4j_mcp_server. Рецепт должен закрепить проверенную версию пакета; naked latest-install не используется в production. [Neo4j quickstart](https://neo4j.com/docs/mcp/current/quickstart/)

Поля рецепта преобразуются в NEO4J_URI, NEO4J_DATABASE, NEO4J_USERNAME, NEO4J_PASSWORD; read-only задаётся NEO4J_READ_ONLY=true. Пароль разрешается только дочернему MCP-процессу. В этой конфигурации при старте проверяются подключение и APOC; мастер должен показать отдельную причину, если зависимость отсутствует. [Neo4j configuration](https://neo4j.com/docs/mcp/current/configuration/)

**Не путать:** адрес neo4j+s://… — адрес базы, а не HTTPS MCP endpoint. Мастер отклоняет неправильный протокол поля.

### Вариант B2: Neo4j Aura / уже опубликованный HTTP MCP

1. Открыть Aura Console и сведения нужного instance.
2. Скопировать MCP URL из сведений экземпляра, если функция доступна. Документация приводит шаблон https://<INSTANCE_ID>.mcp-instances.neo4j.io.
3. В PolyMAS выбрать «HTTPS MCP», вставить endpoint; поля локального Python/NEO4J_PASSWORD env скрываются.
4. Выбрать поддерживаемый способ авторизации, который сообщает сервер/его инструкция: OAuth, bearer либо поддерживаемая gateway схема. Произвольный database password не подставляется автоматически как bearer token.
5. Пройти авторизацию, проверить tools, выполнить разрешённое чтение, назначить bindings.

Доступность Aura MCP для конкретного instance проверяется при настройке. [Neo4j Aura quickstart](https://neo4j.com/docs/mcp/current/quickstart/)

HTTP-режим Neo4j использует request authentication; переменные имени/пароля для STDIO не переносятся на него как универсальная конфигурация. [Neo4j HTTP authentication](https://neo4j.com/docs/mcp/current/authentication/)

### Семантика общей графовой памяти

Простое подключение Neo4j не создаёт готовую память. PolyMAS определяет namespace и типы Document/Claim/Entity/Source/AgentContribution, индексы, provenance и процесс верификации. Инициализация схемы является отдельной write-операцией с просмотром изменений.

Чтение — основной default. Публикация утверждений проходит app-level operation с проверкой namespace, источника и ACL. Raw arbitrary Cypher не используется как безопасная универсальная запись.

Read-only флаг и скрытие write tools дополняются правами DB principal. Разделение namespaces только фильтром промпта недостаточно. Если выбранная редакция/сервер не обеспечивает требуемую изоляцию, используются отдельная база или приложение-посредник.

## 6. Рецепт C: своя БД / PostgreSQL

Первый выпуск предлагает **«Свой MCP-сервер»**. Специализированный PostgreSQL-рецепт добавляется только после выбора издателя, версии и тестов. Образ карточки PostgreSQL на дизайн-референсе — направление каталога, не обещание встроенного проверенного драйвера.

Пользователь получает инструкции:

1. Выбрать поддерживаемый MCP-сервер для своей БД у его издателя.
2. Создать отдельного пользователя с минимальными правами у администратора БД.
3. Настроить сервер согласно его официальному руководству.
4. В PolyMAS добавить STDIO команду/аргументы или HTTPS endpoint.
5. Связать защищённые поля с именами переменных/headers, которые требует именно этот сервер.
6. Выполнить read-only probe и назначить allowlist/namespace.

PostgreSQL connection string не вводится в поле MCP URL. Поля БД должны принадлежать конкретному recipe, иначе wizard показывает обобщённые параметры сервера.

## 7. Рецепт D: удалённое файловое/объектное хранилище

Через «Свой MCP» подключаются серверы для файлового сервиса или S3-совместимого storage. До выбора конкретного сервера приложение не обещает универсальный access key format.

Wizard указывает: где в консоли выбранного поставщика выдать read-only доступ, какие bucket/folder prefixes разрешены, какой endpoint скопировать и какая версия MCP поддерживается. Секреты не записываются в URL.

Контрольная операция читает метаданные/выбранный объект. Большие объекты не целиком загружаются в контекст; используется ограниченный fetch/parser с artifact references.

Для Google Drive/аналогичных сервисов используется штатная OAuth-страница сервиса; пароль не вводится в PolyMAS. Доступ к каталогу и индексация — разные опции.

## 8. Рецепт E: произвольный MCP

Вкладки STDIO / HTTPS. Обязательные поля STDIO: путь к executable, массив args, cwd; HTTP: URL, поддерживаемый auth method. Advanced: env handles, headers from secret refs, timeout, proxy/CA, tool policy.

Свободное поле «вставьте команду» может быть удобным импортом, но до сохранения преобразуется в видимый executable + args, проходит разбор и подтверждение происхождения. Shell operators не исполняются.

Импорт JSON/TOML показывает diff. Нельзя молча выполнить неизвестный npx/uvx download. Каталог имеет pinned package version/checksum, список permissions, документацию и дату проверки. Community connector явно отличается от verified recipe.

Тестирование не выполняет неизвестные write tools. Неизвестный tool классифицируется как требующий явной политики.

## 9. Секреты и ротация

Секрет создаётся в vault, connection хранит secretRef. Renderer видит маску и наличие, не получает сохранённое значение. Значения не входят в экспорт архитектуры, промпты, history и диагностический bundle.

При ротации создаётся новая версия secretRef, проверяется тестовое соединение, новые turn переключаются на новую версию. Старый секрет отзывается после drain или немедленно при компрометации.

OAuth отмена возвращает мастер в исходное состояние. Callback проверяет state/PKCE и допустимый origin в соответствии с используемой библиотекой/протоколом. Не поддерживаемый flow означает понятный отказ, а не ручное копирование чужих токенов.

Кэшированные знания сохраняются только по retention/ACL. Отзыв source binding блокирует будущие чтения, но не удаляет автоматически уже включённый в provider session текст.

## 10. Диагностическая матрица

| Сбой | Сообщение пользователю | Действие системы |
|---|---|---|
| executable not found | «Не найден сервер MCP» | Предложить путь/установку recipe |
| invalid config | «Проверьте поле …» | Не запускать процесс |
| transport timeout | «Сервер не ответил» | Ограниченный retry, safe logs |
| handshake mismatch | «Версия протокола не поддерживается» | Показать совместимые версии |
| 401/auth missing | «Нужно войти или обновить ключ» | Остановить новые обращения |
| 403 | «Учётной записи не хватает доступа» | Не повторять login бесконечно |
| tools empty | «Сервер доступен, инструменты не предоставлены» | Проверить permissions/capabilities |
| DB unavailable | «MCP запущен, база недоступна» | Проверить адрес/сеть/сертификат |
| root denied | «Файл вне разрешённой папки» | Отклонить; не расширять root |
| timeout after write | «Результат операции неизвестен» | Reconciliation до retry |
| revoked during run | «Доступ отозван» | Блокировать новые вызовы, обновить bindings |

Каждый готовый рецепт проходит ту же матрицу в CI и интеграционном стенде. Инструкция «куда зайти и что вставить» поставляется вместе с recipeVersion и обновляется независимо от ядра приложения.
