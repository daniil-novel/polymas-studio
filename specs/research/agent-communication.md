# Общение агентов: исследования и план сравнения

Дата анализа: 2026-09-09. Это инженерный обзор первичных публикаций, а не систематический метаанализ и не рейтинг по цитируемости. Числа из разных работ нельзя сравнивать как результаты одного эксперимента.

## Что уже проверено в этом приложении

Основание: [журнал evidence](../evidence/README.md), D10 и D19. Это функциональные проверки, не исследование относительного качества режимов.

- Настоящий Codex: адресное сообщение, освобождение слота C=1 после reap, пробуждение и resume той же task session. Подтверждает работоспособность доставки и жизненного цикла, не преимущество диалога.
- Настоящий Codex: поиск локального знания и чтение provenance. Первый ответ нарушил формат роли и был отклонён; второй, с согласованным контрактом проверяющего, принят. Это важный пример смешения эффекта памяти с эффектом инструкции роли.
- Внешняя destructive MCP-запись отменена Codex exec 0.144.1 до gateway даже после owner decision. Запись не квалифицирована. Нельзя выдавать protocol fixtures за прошедшую интеграцию провайдера.
- Нет сопоставимых серий «одинаковая задача/роли/модель/бюджет, различается только общение». Нет доказанного выигрыша GraphDB, вики, тысячи процессов или восьмичасовой устойчивости.

## Рекомендация

Разделить четыре независимых решения: **топология доступа**, **протокол обмена**, **представление памяти**, **планирование работы**. Координатор опционален во всех режимах. Для начала — четыре выбираемых протокола одного запуска: адресные сообщения, доска, Markdown-вики, граф утверждений. Их подробный контракт — [ADR-019](../adr/019-communication-modes.md).

Практическая начальная гипотеза: адресный обмен для поручений; доска для независимых результатов; вики для совместного документа; граф для анализа противоречий и многошагового происхождения. Это рекомендация по характеру работы, не объявление победителя. Комбинированный режим и автоматический выбор требуют отдельного измерения.

Один общий Markdown-файл без посредника плохо подходит для конкурентной записи: потерянные обновления, конфликты, переполнение контекста. Вики хранит неизменяемые Markdown-версии и принимает изменение только с ожидаемой версией. Файл можно получить как представление; сервер остаётся единственным писателем хранилища.

## Как сравнивать

1. Набор задач: передача точного факта; сбор независимых свидетельств; совместное исправление документа; разрешение противоречия; задача с недостающими данными; задача с циклом. Заранее фиксировать проверяемые ответы/тесты и критерии отказа.
2. Для каждой задачи одни и те же идентичности агентов и версии ролей, модель, инструменты, входные данные, N/C, топология, сроки, лимит ходов и публикаций. Новые сессии и пустое пространство публикаций в каждом запуске. Не передавать результат предыдущего режима в следующий.
3. Рандомизировать порядок режимов и повторять серии. Хранить исходные результаты всех попыток. Число повторов и стоимость согласовать с бюджетом; один smoke не позволяет делать статистический вывод. Для серьёзной оценки — заранее выбранный размер выборки, парные разности и доверительные интервалы по задачам, а не по сообщениям.
4. Измерять отдельно: объективную правильность/принятие, недостижение критерия, число ходов, длительность, сообщения/публикации/чтения, байты, токены при наличии полного usage, конфликты, отказы доступа и незавершённые вызовы. Отсутствующие токены/стоимость обозначать «нет данных», не нулём. Подписку не пересчитывать в выдуманную цену токена.
5. Сравнение сохранённых запусков показывает наблюдения и совпадение контролируемой конфигурации. Оно не утверждает причинность: нагрузка компьютера, состояние внешних MCP, плавающая модель по умолчанию и версия провайдера могут различаться. Незавершённый запуск не ранжировать как быстрый/успешный.
6. Отдельный слой — детерминированные protocol/regression experiments: повтор после потери ответа, две записи одной версии, restart, чужой run, отзыв ребра, ограничение глубины и бюджета, пагинация. Они проверяют механизм, а не интеллект модели.

Production gates: actual Codex для каждого нового инструмента; воспроизводимая серия с оценкой качества; нагрузка 1000/5000 определений и ограниченным C; отказоустойчивость; внешний Neo4j при настроенном endpoint. До этих проверок UI не должен обещать доказанное превосходство или пройденную production-квалификацию.
