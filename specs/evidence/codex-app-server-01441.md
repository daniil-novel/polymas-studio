# Codex app-server 0.144.1: предварительная квалификация

Дата: 2026-09-08. Статус: **NOT QUALIFIED** для исполнения подтверждённых MCP write операций. Это запись проверки совместимости, не новый разрешённый runtime profile.

## Причина проверки

Реальный exec smoke после точного решения владельца остановился на подтверждении самого провайдера: Codex вернул `user cancelled MCP tool call`, а gateway не получил execute. Внешний fixture не изменился. Полный сценарий и идентификаторы записаны в [общем журнале доказательств](README.md). Повторная выдача разрешения или переименование write-инструмента в read-only не решают эту границу.

## Наблюдения

| Проверка | Результат | Следствие |
|---|---|---|
| Установленный CLI | `codex-cli 0.144.1` | Квалификация относится к этой версии |
| `codex app-server --help` | Команда обозначена experimental; доступен stdio transport | Нельзя незаметно заменить production exec adapter |
| Изоляция через `--ignore-user-config` | Флаг отвергнут и после app-server, и перед подкомандой | Изолированный exec launch нельзя перенести копированием argv |
| Сгенерированные самим CLI stable/experimental JSON Schema | ThreadStartParams имеет config/cwd/sandbox/approvalPolicy; отдельного ignore-user-config/ignore-rules поля нет | Наличие общего config map само по себе не доказывает отсутствие пользовательских MCP, инструкций и расширений |
| ServerRequest schema | Метод `item/tool/requestUserInput`; params связывают threadId/turnId/itemId/questions | Relay должен использовать фактическую версию протокола, а не предполагаемое имя из примера |
| ToolRequestUserInputResponse schema | answers по ID вопроса, внутри массив answers; тип experimental | Нельзя считать любую строку Accept разрешением любой операции |

Документация описывает дополнительное подтверждение для MCP-инструментов приложений с побочными эффектами и отказ исполнения при отклонении. Она также прямо ограничивает поддержку app-server для production. Это подтверждает необходимость отдельной квалификации; **из документации не следует**, что generic STDIO MCP write нашего gateway уже совместим с таким relay. [Официальная документация App Server](https://developers.openai.com/codex/app-server).

Схемы получены локальными generate-json-schema / generate-json-schema --experimental в игнорируемую временную папку. На этом шаге app-server с моделью не запускался, учётные данные не читались и не переносились, пользовательская конфигурация не изменялась. `--strict-config` проверяет неизвестные поля; это не режим отключения пользовательской конфигурации.

## Условия следующего испытания

1. Подтвердить изоляцию configuration/rules/MCP/plugins без копирования auth.json и без изменения пользовательских настроек; проверить на намеренно добавленном постороннем fixture MCP.
2. Связать server request с конкретным процессом агента, thread, turn, item и точной canonical операцией PolyMAS. Сверить инструмент, connection scope и аргументы; всё несовпадающее отклонять.
3. Сначала проверить поддельный request, повтор, отзыв доступа, timeout, обрыв и восстановление на protocol fixture. Запрос разрешения провайдера не заменяет разрешение владельца PolyMAS.
4. Выполнить реальный ограниченный write smoke в тестовый ресурс: одна запись, один durable outcome, повтор без второго эффекта, Unknown при неопределённом исходе.
5. До выбора для production выполнить условия [архитектуры §3.2](../03-architecture.md): поддерживаемый статус либо отдельное решение о риске, версия, compatibility suite и rollback.

Состояние D07b остаётся открытым. Основной exec adapter сохраняет прежнюю политику sandbox/approval.
