# ADR-019 — выбираемые протоколы общения и сопоставление запусков

Статус: принято для реализации, 2026-09-09. Запрос владельца: несколько видов общения с возможностью сравнения. [Исследовательское основание](../research/agent-communication.md).

## Контракт

`Architecture.communicationMode`: `direct` (default для старых конфигураций), `blackboard`, `wiki`, `graph`. Сохраняется в истории и снимке Run; переключение требует существующего owner CAS. Новый доступ не выдаётся старому run; при несовпадении live и pinned режима новые agent-вызовы общения отклоняются. Смена режима не стирает журнал. Топология, координатор и подключённая долговременная память остаются отдельными настройками.

- **Direct**: существующие send/inbox/ack/wait, по одному разрешённому адресату, queued ≠ delivered ≠ acknowledged. Остальные режимы используют явное чтение общих публикаций; публикация не запускает задачу и не подтверждает приёмку. Ожидание сообщений не подменять скрытым busy loop.
- **Blackboard**: неизменяемые отдельные записи, чтение страницами, автор/run/время. Повтор одного idempotencyKey возвращает ту же запись. Изменить запись нельзя.
- **Wiki**: страницы с коротким slug, заголовком и Markdown. Создание expectedRevision=0; изменение требует точной текущей версии. Все версии сохраняются. При конфликте агент читает свежую страницу и предлагает новое изменение с новым ключом. История не затирается; нет автоматического слияния или записи произвольного пути на диск.
- **Graph**: неизменяемые утверждения и типизированные ссылки `supports`, `contradicts`, `derived_from` на существующие записи этого запуска. Корни допустимы. Ссылка на будущую запись невозможна, поэтому причинный граф ацикличен, хотя агенты могут обсуждать тему многократно. Глубина ≤ messageHopLimit, ссылки ≤8, contributors ≤32. Цикл «прочитать → предложить → критиковать → уточнить» выполняется явными ходами агента с общим maxTurns и бюджетом публикаций. Это локальный граф обсуждения; он не называется готовым GraphRAG/Neo4j.

## Доступ, хранение, пределы

Служба назначает sender/run/attempt, агент не передаёт их в аргументах. Доступ к чужому содержимому требует действующего направления author→reader одновременно в pinned и live топологии и активных участников в обеих конфигурациях. Собственную запись можно читать. Wiki revision/graph reference наследуют contributors; доступ нужен от каждого contributor, включая автора. Это предотвращает расширение доступа через структурную ссылку; семантическое копирование моделью отдельно остаётся проблемой управления данными.

Записи изолированы по workspace/run/mode; серверные страницы фильтруют права **до** LIMIT. Владелец читает историю выбранного run через owner API. Независимая архитектура не получает неявный общий канал. Архивирование и отзыв ребра действуют немедленно. Память долгого срока из D19 имеет собственные bindings и не становится публичной из-за выбора вики.

Атомарная запись в SQLite: immutable revision + обновление head + receipt + событие в одной транзакции. IdempotencyKey scoped по run/author, повтор с иными параметрами — conflict; повтор не расходует бюджет. Общий предел сообщений/публикаций ≤ maxMessagesPerRun. Заголовок ≤200 UTF-8 bytes, Markdown ≤16 KiB, slug ≤80 ASCII `[a-z0-9_-]`, ключ ≤128 bytes; страницы ≤50 записей. Содержимое — недоверенные данные, UI выводит его текстом без HTML. Нельзя публиковать credentials, скрытые рассуждения или самопровозглашённый verified status.

MCP: отдельные read и publish tools, строгие схемы. Publication — state-changing, append-only/idempotent, без внешнего мира; исторические данные не удаляются. Чтение не означает, что модель усвоила материал. Gateway пишет metadata событий чтения/публикации без тела. Соблюдать текущие approvals провайдера; нельзя менять annotations для обхода отказа.

## Экран

В редакторе архитектуры — выбор «Способ общения» и краткое объяснение поведения каждого режима, связь с будущими запусками и текущими правилами доступа. Раздел «Общение»: выбор сохранённого запуска, его фактический режим, публикации/версии/связи с происхождением, текстовый просмотр Markdown; пустое состояние с инструкцией. Содержимое страниц загружается ограниченными страницами, поздние ответы прежнего запуска игнорируются. Прямой режим объясняет доставку следующему ходу и ведёт к трассе запуска.

Сравнение 2–4 сохранённых запусков: фактический режим, задачи/принятые/ошибки/незавершённые, ходы, объём обмена. Проверять совпадение входа, ролей, бюджета и архитектуры кроме режима/визуальных позиций; показывать различия и отсутствие контроля вместо рейтинга. Наличие принятой задачи не является независимой оценкой factuality. Из UI доступны свежая загрузка и состояние ошибки; сбой сети не оставляет старое сравнение под новыми названиями.

## Критерии приёмки

TDD: старый JSON→direct, неизвестный режим отвергается; выбор сохраняется и pinning работает. Board retry/reopen/лимиты; wiki CAS при конкурентных соединениях без потери версии; graph references/depth/cross-run/access; agent identity не подделывается; filtered paging; revoke и late grants; owner HTTP auth; сопоставление не скрывает различия/неполные данные; UI selection/retry/stale-response, узкое окно и CU.

Синтетические проверки механизма, actual provider smoke и измерение качества — три разных статуса. Открытые gates сохраняются в TASKS и evidence; внедрение режимов не закрывает весь production roadmap.
