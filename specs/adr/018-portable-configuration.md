# ADR-018 — переносимая конфигурация экземпляров

Статус: принято для D12c. Основание: FR-01, FR-16, UI-13.

Blueprint `architecture.schema.json` описывает создание populations. Он не сохраняет все поля материализованных экземпляров, версий ролей и прав. Экспорт текущей системы использует отдельный `configuration-export.schema.json`: format `polymas-configuration`, schemaVersion `0.1.0`, migrationVersion `1`, sourceRevision, name, runtime, roleVersions, instances, architecture, connections и bindings. Старый blueprint остаётся самостоятельным контрактом; автоматическое преобразование между форматами не заявляется.

Экспорт строится явной проекцией разрешённых полей, а не удалением известных секретных ключей из полного snapshot. Сохраняются все версии ролей, конкретные ID/имена/назначения и признак архива, состав холонов, координаторы, связи, pins и ограничения сообщений/C. Нет workspace paths, session IDs, fork lineage, batch receipts, process/runtime records, task/result/message/approval/knowledge history, артефактов, дат создания и адресов vault. Тексты ролей, имена, цели холонов и namespaces — содержимое конфигурации, введённое владельцем; оно сохраняется дословно и требует просмотра перед передачей файла. Автоматическое распознавание секретов внутри произвольного текста не обещается.

Каждое подключение заменяется placeholder: ID, имя, recipe, тип транспорта, readOnly, timeoutSeconds, toolAllowlist, desiredEnabled, setupRequired=true и список требуемых полей настройки. URL, executable, args, roots, environment (включая значения обычных переменных), ссылки/значения секретов, обнаруженные descriptors и диагностика не экспортируются. Для файлов сохраняется только количество папок; новые roots выбираются при импорте. Факт необходимости auth/environment отражается boolean/названиями полей настройки без прежних значений. Runtime сохраняет только codex-exec и setupRequired=true.

Architecture в файле всегда paused=true. memoryEnabled и desiredEnabled выражают желаемую конфигурацию, не предоставляют действующего доступа. Импорт обязан создать новую рабочую область и новые agent/session identities с таблицей соответствий всем внутренним ссылкам; проверить версию формата, ссылки/топологию, выбранные пути, runtime и права; подключения остаются disabled/unconfigured до отдельной проверки. Экспорт не является backup или разрешением автоматически запускать процессы/подключения.

Owner GET `/api/exports/configuration` читает один согласованный snapshot и возвращает человекочитаемый JSON до 16 МиБ. Превышение размера/числа подключений отклоняется целиком, без усечения или частичного файла. Чтение не меняет revision/event head и не обращается к внешним источникам. Endpoint использует общую owner authentication, no-store и nosniff; gateway credential не даёт доступа. Пользовательский экран сначала читает экспорт по запросу, показывает состав и исключения, затем сохраняет именно просмотренную версию. Импорт/backup UI квалифицируются отдельными срезами.
