# ADR-016 — чтение записи запуска

Статус: принято для D19h. Основание: FR-12 и UI-10.

`GET /api/runs/{id}/recording` читает конфигурацию из `configuration_history` по неизменяемой `configRevision` запуска. Возвращает описание графа, имена версий ролей, идентификаторы/зависимости задач и верхнюю границу `head`. Текущие состояния, результаты, prompts и инструкции ролей не включаются в manifest. Граница фиксируется под тем же mutex службы, что и чтение конфигурации; открытие записи не меняет scheduler.

`GET /api/runs/{id}/recording/events?after=0&through={head}&limit=500` возвращает только события этого запуска с `after < sequence <= through`. Следующая страница получает прежний `through` и возвращённый `cursor`. `complete=true` продвигает cursor до through, включая пустые промежутки между запусками. Страница ограничена 500 событиями и 2 МиБ; manifest ограничен 8 МиБ. Это owner API с общей авторизацией, не gateway capability. Индекс `(run_id,sequence)` уже существует.

Воспроизведение использует sequence как порядок истины. Временная шкала не должна переставлять события при обратном скачке системных часов; для проигрывания применяется монотонная позиция `max(previous + 1 ms, observedAt)`, оригинальное время остаётся в карточке события. Состояние агента в записи означает последнее записанное состояние задачи, а не текущий живой процесс. Наблюдаемые `runtime.heartbeat` доступны в журнале, но replay не выдаёт записанное task state за текущую свежесть lease и не выдумывает PID, скрытое рассуждение или успешное завершение между событиями. Сообщения/чтения памяти подсвечиваются только по соответствующим наблюдаемым событиям.

Первый UI читает страницы последовательно, сохраняет компактные метаданные (до 100 000 событий), а полный body выбранного события запрашивает отдельно. При превышении предела явно сообщает об ограничении без молчаливого усечения. Индекс состояния по задачам и двоичный поиск используются при перемотке; виртуальный список не создаёт DOM для всех событий. Длительные записи сверх предела требуют отдельной серверной проекции с checkpoints; этот масштабный gate остаётся открытым.

UI записи отделён от текущего task editor, явно помечен «Запись», не содержит исполнения/приёмки/конфигурационных команд. Пауза и переход по времени управляют только просмотром. Для следующего запуска требуется явно вернуться к текущему редактору. Полная история, редактор DAG, импорт/экспорт записи и масштабные performance gates остаются отдельными задачами, а не считаются завершёнными этим API.
